# Issue Lifecycle

## States

1. **Backlog** — idea/work identified but not contributor-ready.
2. **Ready** — scope, acceptance criteria, dependencies, tests, and security expectations are clear.
3. **Assigned / In Progress** — contributor is actively working.
4. **Review** — linked PR is under review.
5. **Blocked** — dependency or decision prevents progress.
6. **Done** — accepted implementation/documentation is merged and the issue can close.

## Contributor-Ready Criteria

A Ready issue should include context, goal, scope, technical requirements, security considerations, acceptance criteria, testing requirements, out-of-scope notes, dependencies, definition of done, and intended labels/milestone.

## Assignment

Where contribution programs require assignment, contributors should not begin substantial work before assignment. Maintainers should avoid parallel assignments unless collaboration is intentional.

## Scope Changes

If implementation reveals materially larger work, discuss it before expanding the PR. Split new work into follow-up issues rather than silently broadening scope.
